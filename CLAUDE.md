# Project guide for coding agents

Unofficial Stream Deck plugin "Home Weather Station" (plugin id
`de.schwetschke.sd.home-weather-station`): shows data from a Netatmo weather station on keys and
dials. Public repository, MIT, non-commercial. `AGENTS.md` is a symlink to this file.

Read first: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) (the contract between layers),
`src/adapter/station/types.ts` and `service.ts`, `src/pi-protocol.ts`. Other docs: SETUP, BRANDING,
PUBLISHING, WEATHER-API (sourced API facts), RENDERING (artwork), `SECURITY.md`, `CONTRIBUTING.md`.

## Commands

Use `devenv shell -- <cmd>` (or direnv) so node 24, pinact, osv-scanner, gitleaks, zizmor and actionlint are on
PATH. The project's scripts (`scripts/*.ts`) run with Node 24's own type stripping (no tsx): imports carry `.ts`
extensions and sources use no enums, namespaces or parameter properties.

```sh
npm ci
npm run typecheck                     # tsc over src, tests, scripts (tsconfig.typecheck.json)
npm test                              # node --test tests/*.test.ts  (one file: node --test tests/<name>.test.ts)
npm run build                         # sync version + rollup -> <plugin>.sdPlugin/bin/plugin.js
npm run validate                      # streamdeck validate
npm run pack                          # verify:manifest + streamdeck pack -> .streamDeckPlugin (git-ignored)
npm run watch                         # dev loop; adds Nodejs.Debug "enabled" LOCALLY, never commit that
npm run generate                      # icons + manifest from the action catalog
npm run probe                         # real API, needs secretspec credentials (see README); not run by CI
npm run capture:fixture -- <raw.json> # anonymises a raw probe capture; needs no secrets
npm run scan:vulns                    # osv-scanner; accepted advisories with expiry are in osv-scanner.toml (SECURITY.md)
```

Only the plugin-layer owner runs `build`/`validate`/`pack` when several agents work in parallel.

## Layout

```
src/plugin.ts            entry: registers actions, the single settings writer, wires the poller
src/actions/*            SDK layer (key and dial actions); catalog.ts holds the plugin id
src/focus/*              pure navigation over the focus (station, module, metric), auto-rotate, focus store; SDK-free
src/render/*             pure: snapshot + settings + now -> SVG string / title / feedback; display units (format.ts)
                         and freshness/status (status.ts) live here
src/adapter/station/*    SDK-FREE: credentials, token manager, HTTP client, parser, history, poller, browser sign-in
src/pi-protocol.ts       event names and message shapes shared with the Property Inspector
<plugin>.sdPlugin/ui/    Property Inspector: static HTML, ui/init/*.js, vendored sdpi-components
scripts/*.ts             generators (manifest, icons), probe, fixture capture, version sync
tests/*.test.ts          flat directory, so the unquoted glob stays portable
```

## Rules that bite (each cost real time in the sibling project this was derived from)

1. **Manifest `Nodejs.Debug` must be ABSENT** in everything committed or packed. `"enabled"` opens a
   Node inspector port and flips the SDK to TRACE logging (which dumps settings); `"disabled"` makes Stream Deck
   refuse to start the plugin (exit code 1 before any JS runs, nothing in the plugin log). `npm run build`
   removes the key; a pre-commit hook and `verify:manifest` guard it.
2. **Manifest `Version` is 4-part** (`X.Y.Z.0`), derived from `package.json` by `scripts/sync-manifest-version.ts`
   as the first step of `build`. The CLI rejects 3-part versions. Never edit it by hand.
3. **Plugin id == `.sdPlugin` folder name == action UUID prefix.** One source: `src/actions/catalog.ts` for
   code, `scripts/lib/plugin-id.ts` for scripts. `manifest.json` is generated by `scripts/generate-manifest.ts`
   so code and manifest UUIDs cannot drift. Do not hard-code the id elsewhere (exceptions: `package.json`
   scripts, `rollup.config.mjs`).
4. **`setImage` needs a data URI for composed SVG.** Wrap as `data:image/svg+xml;base64,...`. A raw SVG
   string is silently ignored for composed images on hardware (measured in the sibling project; not yet verified
   for this plugin) and the key falls back to its manifest icon with no error anywhere. Use `href` only,
   not `xlink:href` as well (doubles the payload).
5. **Single settings writer.** `plugin.ts` is the only caller of `setGlobalSettings`, through one funnel gated on a
   successful initial load, and it updates the cache itself (the SDK does not echo own writes). A test greps for
   this. The PI never uses sdpi's `global` binding; it goes through `sendToPlugin`.
6. **No secrets in logs, settings or the PI.** Tokens, client secret, Authorization headers, URLs with query
   strings, raw API bodies: never logged. Module ids (MAC addresses) not at INFO. Credentials live only in the
   `0600` file; the PI gets `CredentialSummary`/`AccountStatus`. Untrusted strings go through the truncating log
   helper. At TRACE the SDK dumps whole settings and every frame; release builds ship at INFO.
7. **The adapter is SDK-free**: `src/adapter/**` and tests never import `@elgato/streamdeck` (its import rotates
   log files as a side effect and races between parallel test processes). Log via `scopedLogger`; `plugin.ts`
   injects the SDK logger.
8. **Repaint from cache, status is a pure function.** Actions never query the API; the single poller owns all
   traffic (default 300 s, floor 60 s, jitter, backoff, `Retry-After`). What a key shows for stale, unreachable,
   auth-error or no-credentials is computed in the normal render from `ConnectionState` + `Freshness`; no second
   write path that could outlive an outage. Freshness comes from `measuredAt`, not from `reachable`.
9. **Token rotation.** Netatmo invalidates the old refresh token at every refresh: single-flight refresh, try to persist atomically BEFORE returning the new access token (if both attempts fail the pair stays in memory, the poller publishes an `ok` ConnectionState with `warning: "unpersisted-rotation"` (text `UNPERSISTED_ROTATION_MESSAGE`), shown in the Property Inspector's status line AND as a warning marker on the keys (values stay at full opacity), the write is retried on every poll, and a restart before a successful write means signing in again; see SECURITY.md; never describe this as "no silent fallback" or hide it), refresh early, treat `invalid_grant` / 403 code 30
   as auth-error and stop polling. Never register webhooks (one URL per app would replace another client's).
10. **Every SDK promise is caught** (`fireAndLog`): Node 24 treats an unhandled rejection as fatal, and a failed
    `registerAction` is swallowed by the uncaught-exception net while the process still exits 0, so the bundle test looks for
    a log marker, not an exit code, and has a negative control.
11. **API strings never become SVG markup** (module and station names are user-controlled): keep them in the native
    title or escape them. Quantise values to the displayed precision before composing, so `writeKeyFace`
    de-duplication holds.
12. **Property Inspector**: vendored sdpi-components (no CDN), CSP `script-src 'self'` (no inline script; init code
    in `ui/init/*.js`). `sdpi-select` only picks up `<option>`s added after it upgraded: use the datasource round
    trip. Always send an items array in datasource replies (no items blanks the dropdown). Plain text in a PI is
    black on a dark panel: use the shared classes, do not dim with opacity.
13. **Silent-failure checks.** Unknown layout keys and missing image paths do nothing and log nothing; tests
    assert them. Validate a filter before trusting "no matches" (the hygiene test feeds a sample first).
14. **Node test runner strips types only.** No enums, no constructor parameter properties, no namespaces; `.ts`
    extension in every relative import; no raw control bytes and no invisible or bidirectional characters
    (U+200B-200F, U+202A-202E, U+2066-2069, U+FEFF) in sources: use `\u` escapes (a pre-commit hook and
    `tests/repo-hygiene.test.ts` enforce it).
15. **Toolchain pins.** TypeScript stays on 6.x: 7 type-checks but `rollup -c` dies in
    `@rollup/plugin-typescript`; see the comment in `.github/dependabot.yml` before touching it. Check bumps with
    `npm run build`, not `npm run typecheck`.
16. **After a plugin crash loop** Stream Deck marks the plugin unstable and stops launching it;
    `streamdeck restart` does not clear that, restarting the Stream Deck app does (sibling-project observation).
17. **CI hygiene.** Every action pinned to a full commit SHA with a `# vX.Y.Z` comment (`tests/workflows.test.ts`,
    `pinact run --check`). Re-resolve SHAs via the GitHub API, not from memory. The release workflow keeps the
    write token away from everything that runs npm (build job read-only with `npm ci --ignore-scripts`; the upload
    job has no checkout and no npm); `tests/workflows.test.ts` pins that. New actions need `scripts/github-settings.py`
    (`--check`, then `--apply` after review).

## Brand and privacy rules (tests enforce the mechanical part)

- "Netatmo", "Elgato", "Corsair" and "Legrand" must never appear in the manifest `Name`, `Category`, `Author`,
  any UUID, file or folder names, icons, the package name or the repository name. "Stream Deck" and "plugin" must
  not appear in manifest `Name`, `Category`, `Author` or any UUID; "Stream Deck" is allowed descriptively in the
  repository and package slug `stream-deck-home-weather-station`. "Netatmo" appears only as a
  compatibility statement in running text, with the non-affiliation notice (README first lines, NOTICE).
  Write "Stream Deck" as two words, "plugin" without hyphen. No Netatmo/Elgato/Corsair logos, product photos, brand
  colours as identity. Nothing commercial: no ads, paid tier, donation links ([docs/BRANDING.md](docs/BRANDING.md)).
- Never write real or realistic personal data or internal identifiers into the repo (names, e-mail addresses,
  account ids, real MAC addresses, coordinates, station names, ticket or PR numbers, other people's repo slugs).
  Fixtures are fictional: MAC addresses from `00:00:5e:00:53:xx`, IPs from RFC 5737, names like "Test Station".
  When pasting example output, replace EVERY identifier on the line. Search by identifier format, not by keyword.
  `tests/repo-hygiene.test.ts` does that; do not widen its allowlist without a written reason. The same holds
  for `.gitleaks.toml` (path AND regex scoped to two tests' fake sentinels); never widen it to silence a finding.
  The gitleaks hooks run through `scripts/gitleaks-local-secrets.py`, which also matches the real values of
  the git-ignored `.env.local`; never print, copy or commit those values, and never pass them on a command line.
- Do not copy identifying data (devices, hosts, names, addresses) from the sibling project; copy patterns only.
- Do not claim anything that was not verified. There are no live API results and no hardware results unless a doc
  says otherwise; mark such statements **[unverified]** in docs and comments.

## Working conventions

- Conventional Commits (`feat:`, `fix:`, `docs:` ...); release-please does versions and the changelog.
  Do not commit or push unless asked.
- Comments explain WHY and carry measured or sourced facts. Prefer small pure functions with unit tests.
- Use `npm ci`; a dependency change is a
  supply-chain decision (14-day cooldown in Dependabot, `osv-scanner`).
- Never edit `osv-scanner.toml` to silence a new finding without a reason and an `ignoreUntil` date.
- Releases: GitHub Releases only, never the Elgato Marketplace ([docs/PUBLISHING.md](docs/PUBLISHING.md)).
